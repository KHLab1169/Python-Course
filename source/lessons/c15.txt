=== 15.1
@idea
**Screen scraping** means pulling information out of web pages that were written for people, not programs. A page is HTML: text marked up with **tags** like `<h1>`, `<a href="...">` and `<td>`, nested inside each other. To extract data you read the HTML, find the tags you care about and collect their text or attributes.

Python's built-in `html.parser` module reads HTML as a stream of events. You subclass `HTMLParser` and override methods: `handle_starttag(tag, attrs)` is called for each opening tag, `handle_endtag(tag)` for each closing one, and `handle_data(data)` for the text in between. Your class keeps whatever state it needs, such as "am I inside a heading right now?". This needs nothing installed, and it is a good way to understand how HTML is structured.

For real projects most people use **Beautiful Soup** (`pip install beautifulsoup4`), which builds a tree you can search: `soup.find_all("a")`, `soup.select("table.prices td")`. It copes well with the messy HTML found on real sites. Whichever you use, check a site's terms of use and `robots.txt`, keep requests slow and few, and prefer an official API (lesson 15.3) when one exists.
@how
- Subclass `HTMLParser`; call `super().__init__()` in `__init__`; feed text with `parser.feed(html)`.
- `handle_starttag(self, tag, attrs)`: `attrs` is a list of `(name, value)` pairs; `dict(attrs)` makes it easy to read.
- `handle_data(self, data)`: text between tags; track where you are with flags.
- `handle_endtag(self, tag)`: reset flags when an element closes.
- Beautiful Soup: `BeautifulSoup(html, "html.parser")`, then `find`, `find_all`, `select`, `.get_text()`, `["href"]`.
- Scrape politely: respect robots.txt and terms, add delays, use an API when available.
@example python: Collecting links with html.parser
from html.parser import HTMLParser

page = """
<html><body>
  <h1>Python resources</h1>
  <p>Start with the <a href="https://docs.python.org/3/tutorial/">official tutorial</a>,
     then try <a href="https://realpython.com" class="ext">Real Python</a>.</p>
  <a name="top">Back to top</a>
</body></html>
"""

class LinkCollector(HTMLParser):
    def __init__(self):
        super().__init__()
        self.links = []
        self._href = None

    def handle_starttag(self, tag, attrs):
        if tag == "a":
            self._href = dict(attrs).get("href")

    def handle_data(self, data):
        if self._href and data.strip():
            self.links.append((data.strip(), self._href))

    def handle_endtag(self, tag):
        if tag == "a":
            self._href = None

parser = LinkCollector()
parser.feed(page)
for text, url in parser.links:
    print(f"{text}: {url}")
@note
The parser remembers the `href` when an `<a>` opens and pairs it with the link's text. The `<a name="top">` has no href, so it is skipped. `dict(attrs)` turns the attribute pairs into a dictionary that is easy to read.
@example python: The same kind of job with Beautiful Soup
from bs4 import BeautifulSoup

html = """
<table class="prices">
  <tr><th>Tea</th><th>Price</th></tr>
  <tr><td>Sencha</td><td>12.50</td></tr>
  <tr><td>Assam</td><td>9.00</td></tr>
  <tr><td>Rooibos</td><td>7.25</td></tr>
</table>
"""

soup = BeautifulSoup(html, "html.parser")
rows = soup.select("table.prices tr")[1:]           # skip the header row
prices = {r.find_all("td")[0].get_text(): float(r.find_all("td")[1].get_text()) for r in rows}
print(prices)
print("cheapest:", min(prices, key=prices.get))
print([th.get_text() for th in soup.find_all("th")])
@note
`select` uses CSS selectors, the same ones used to style pages, so "rows of the table with class prices" is one short string. Beautiful Soup builds a tree, which makes nested data like tables much easier than tracking flags by hand.
@mistakes
- **Parsing HTML with plain string methods or regular expressions.** Attributes can be in any order and tags nested in surprising ways. Use a parser.
- **Forgetting `super().__init__()` in an HTMLParser subclass.** The parser is not set up and `feed` fails.
- **Assuming the page never changes.** A site redesign breaks scrapers. Check for missing elements instead of crashing.
- **Scraping when an API exists.** APIs are stable, documented and allowed; scraping may not be.
@keys
- Scraping extracts data from HTML meant for people.
- `HTMLParser` calls your methods for start tags, end tags and text; track state with attributes.
- Beautiful Soup builds a searchable tree with `find_all` and CSS `select`.
- Scrape politely and prefer official APIs.

=== 15.2
@idea
A **dynamic** web page is generated by a program each time someone asks for it, instead of being a fixed file. The web server receives a request, runs your Python code, and sends back whatever HTML (or JSON) your code returns. The book describes CGI, an early way of doing this where the server starts your script for every request. It still works, but today Python web apps use a framework that runs continuously and routes requests to functions.

**Flask** is a small, popular framework. You create an app, then decorate functions with `@app.route("/path")`: when a request for that path arrives, Flask calls the function and sends its return value to the browser. Parts of the path can be variables (`/hello/<name>`), and `request` gives access to form fields and query parameters. **Templates** (Jinja) mix HTML with placeholders like `{{ name }}`, and they **escape** values automatically, so text typed by users cannot inject HTML or scripts.

Forms complete the picture. A `<form method="post">` sends its fields back to the server; the route accepts `methods=["GET", "POST"]` and reads `request.form["field"]`. After handling a POST, redirect to a GET page, so refreshing the browser does not submit the form twice.
@how
- `app = Flask(__name__)`; `@app.route("/")` above a function that returns text or HTML.
- Variables in routes: `@app.route("/hello/<name>")` passes `name` to the function.
- `request.args.get("q")` reads `?q=...`; `request.form["name"]` reads posted form fields.
- `render_template_string` (or `render_template` with files in a `templates` folder) fills `{{ }}` placeholders, escaping values.
- `methods=["GET", "POST"]` for routes that receive forms; `redirect(url_for("view"))` after a POST.
- `app.run(debug=True)` starts a development server; `app.test_client()` lets you call routes from code or tests.
@example python: Routes, variables and safe templates
from flask import Flask, render_template_string, request

app = Flask(__name__)

PAGE = "<h1>Hello, {{ name }}!</h1><p>You asked for {{ count }} cups.</p>"

@app.route("/")
def home():
    return "<h1>Tea shop</h1>"

@app.route("/hello/<name>")
def hello(name):
    cups = request.args.get("cups", "1")
    return render_template_string(PAGE, name=name, count=cups)

client = app.test_client()                 # call the app without a browser
print(client.get("/").get_data(as_text=True))
print(client.get("/hello/Ada?cups=3").get_data(as_text=True))
print(client.get("/hello/Ben", query_string={"cups": "<script>alert(1)</script>"}).get_data(as_text=True))
print(client.get("/nowhere").status_code)
@note
`test_client()` sends requests straight to the app, which is how Flask apps are tested; with `app.run()` a browser would see the same pages. The template escaped the script tag sent in the query string into harmless text, so a browser would show it instead of running it. A path with no route gives status 404.
@example python: A form that posts and redirects
from flask import Flask, redirect, render_template_string, request, url_for

app = Flask(__name__)
names = []

PAGE = """<form method="post"><input name="name"><button>Sign</button></form>
<ul>{% for n in names %}<li>{{ n }}</li>{% endfor %}</ul>"""

@app.route("/", methods=["GET", "POST"])
def guestbook():
    if request.method == "POST":
        name = request.form.get("name", "").strip()
        if name:
            names.append(name)
        return redirect(url_for("guestbook"))
    return render_template_string(PAGE, names=names)

client = app.test_client()
reply = client.post("/", data={"name": "Ada"})
print(reply.status_code, reply.headers["Location"])
client.post("/", data={"name": "  "})
client.post("/", data={"name": "Grace"})
print(client.get("/").get_data(as_text=True).split("<ul>")[1])
@note
The POST adds the name and answers with a 302 redirect back to the same page, so a browser refresh would not sign twice. The blank name is ignored. The template's `{% for %}` loop builds one list item per name.
@mistakes
- **Building HTML with f-strings from user input.** That allows script injection. Use templates, which escape values.
- **Handling a POST without redirecting.** Refreshing re-sends the form. Redirect to a GET page after success.
- **Using `debug=True` on a public server.** The debugger lets visitors run code. Keep it for your own machine.
- **Expecting the `names` list to survive a restart.** It lives in memory. Use a database (chapter 13) for anything that must persist.
@keys
- Dynamic pages are generated per request; Flask maps URLs to Python functions with `@app.route`.
- Route variables and `request.args` / `request.form` bring data in.
- Templates fill `{{ }}` placeholders and escape values for safety.
- After a POST, redirect; test apps with `app.test_client()`.

=== 15.3
@idea
A **web service** (or API) is a web address that returns data for programs instead of pages for people, usually as **JSON**. Weather, maps, payments, translations and most modern apps work by calling such services. Using one is simply an HTTP request whose response body is JSON text, which Python turns into dictionaries and lists.

The **requests** library makes this pleasant: `requests.get(url, params={...}, timeout=10)` builds the query string for you, `response.status_code` and `response.raise_for_status()` handle errors, and `response.json()` parses the body. Sending data is `requests.post(url, json={...})`. Many APIs need a key, which goes in a header or parameter and should be read from an environment variable, never written into your code.

The other side is just as easy: a Flask route that returns a dictionary sends it as JSON with the right `Content-Type`. Your web app can then serve both humans (HTML pages) and programs (JSON endpoints) from the same data.
@how
- `requests.get(url, params={"q": "tea"}, timeout=10)`; `requests.post(url, json=data, timeout=10)`.
- `response.raise_for_status()` raises for 4xx and 5xx codes; `response.json()` parses JSON.
- Catch `requests.RequestException` for network problems (it covers connection errors and timeouts).
- Read API keys from `os.environ`; send them as documented (often a header).
- In Flask, return a dictionary or `jsonify(...)` to send JSON.
- Respect rate limits and cache answers that do not change often.
@example python: Calling a JSON API (served locally for this example)
import threading
import requests
from flask import Flask, request

api = Flask(__name__)

@api.route("/weather")
def weather():
    city = request.args.get("city", "")
    data = {"montreal": {"temp_c": -3, "sky": "snow"}, "toronto": {"temp_c": 1, "sky": "cloudy"}}
    if city.lower() not in data:
        return {"error": f"unknown city {city!r}"}, 404
    return {"city": city.title(), **data[city.lower()]}

import logging
logging.getLogger("werkzeug").setLevel(logging.ERROR)   # hide the server's request log
from werkzeug.serving import make_server
server = make_server("127.0.0.1", 0, api)
threading.Thread(target=server.serve_forever, daemon=True).start()
BASE = f"http://127.0.0.1:{server.server_port}"

for city in ["Montreal", "Atlantis"]:
    try:
        r = requests.get(f"{BASE}/weather", params={"city": city}, timeout=5)
        r.raise_for_status()
        info = r.json()
        print(f"{info['city']}: {info['temp_c']} °C, {info['sky']}")
    except requests.HTTPError:
        print(f"{city}: HTTP {r.status_code}, {r.json()['error']}")
server.shutdown()
@note
A tiny Flask service stands in for a real weather API so the example runs without the internet. `params` builds the `?city=...` part safely. `raise_for_status` turns the 404 into an exception, and the error body is still readable JSON.
@example python: Errors, timeouts and API keys
import os
import requests

def get_json(url, **params):
    key = os.environ.get("WEATHER_API_KEY", "demo-key")
    try:
        r = requests.get(url, params=params, headers={"Authorization": f"Bearer {key}"}, timeout=2)
        r.raise_for_status()
        return r.json()
    except requests.Timeout:
        return {"error": "the service took too long"}
    except requests.ConnectionError:
        return {"error": "could not reach the service"}
    except requests.HTTPError as e:
        return {"error": f"service answered {e.response.status_code}"}

print(get_json("http://127.0.0.1:9/never-listening", city="Paris"))
print(requests.Request("GET", "https://api.example.com/v1/weather", params={"city": "Saint-Jérôme", "units": "metric"}).prepare().url)
@note
Port 9 has nothing listening, so the request fails with a ConnectionError and the function returns a clear message instead of crashing. The last line shows how `params` encodes accents and spaces correctly in the URL. The key comes from an environment variable, with a placeholder when it is not set.
@mistakes
- **No timeout.** `requests.get(url)` can wait forever. Always pass `timeout=`.
- **Calling `.json()` without checking the status.** An error page may not be JSON. Call `raise_for_status()` first.
- **Putting API keys in your code.** They end up on GitHub. Read them from environment variables or a config file kept out of version control.
- **Building query strings by hand.** Spaces and accents break the URL. Use `params=`.
@keys
- Web services return data (usually JSON) for programs.
- `requests.get(..., params=..., timeout=...)`, `raise_for_status()` and `.json()` cover most calls.
- Catch `requests.RequestException` subclasses for network problems; keep keys in environment variables.
- A Flask route that returns a dictionary is a JSON API.

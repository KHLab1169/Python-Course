=== 1.1/2
Q: Using the same rules, what does `(10 - 4) * 2 ** 3` give?
+ `48`
- `216`
- `64`
- `1728`
RUN: (10 - 4) * 2 ** 3
WHY: Brackets first (6), then the power (2 ** 3 = 8), then the multiplication: 6 × 8 = 48.

=== 1.1/3
Q: Which line of an error message tells you what went wrong?
+ The last line, such as `ZeroDivisionError: division by zero`.
- The first line, `Traceback (most recent call last):`.
- The line with `...`.
- There is no such line; you have to guess.
WHY: Python lists where the error happened first and ends with the error's type and a message. Read error messages from the bottom up.

=== 1.2/2
Q: 100 eggs are packed in boxes of 12. What does `100 // 12, 100 % 12` give?
+ `(8, 4)`
- `(8.333333333333334, 4)`
- `(8, 0)`
- `(9, 4)`
RUN: 100 // 12, 100 % 12
WHY: `//` counts full boxes (8 × 12 = 96) and `%` gives the leftover (100 − 96 = 4).

=== 1.2/3
Q: What does `-3 ** 2` give?
+ `-9`
- `9`
- `-6`
- `6`
RUN: -3 ** 2
WHY: `**` binds tighter than the minus sign, so this is `-(3 ** 2)`. Write `(-3) ** 2` to get 9.

- `That is 432 months old.`
- `That is 36 months old.`

WHY: `age` was converted with `int()`, so `(age + 1) * 12` is arithmetic: 37 × 12 = 444. Without `int()`, the text "36" would have been repeated instead.

=== 1.3/3
Q: With `answer = "4"`, what does `answer * 2 + "!"` give?
+ `'44!'`
- `'8!'`
- `9`
- `'4 4!'`
RUN: answer = "4"; answer * 2 + "!"
WHY: Multiplying a string repeats it, so `"4" * 2` is `"44"`, and `+` joins text. To do arithmetic, convert first with `int(answer)`.

=== 1.4/2
Q: What does `round(6.5), round(9.5)` give?
+ `(6, 10)`
- `(7, 10)`
- `(6, 9)`
- `(7, 9)`
RUN: round(6.5), round(9.5)
WHY: Python rounds halves to the nearest even number ("banker's rounding"), so 6.5 goes down to 6 and 9.5 goes up to 10.

=== 1.5/3
Q: Why is the constant written `SECONDS_PER_DAY` in capitals?
+ It's the usual way to mark a value that never changes.
- Python requires constants to be in capitals.
- Capital names run faster.
- It makes the value impossible to change.
WHY: The capitals are a convention for readers. Python doesn't stop you from reassigning it, but everyone knows not to.

=== 2.2/2
Q: With `date = "2026-11-20"`, what does `date[5:]` give?
+ `'11-20'`
- `'-11-20'`
- `'11'`
- `'2026-'`
RUN: date = "2026-11-20"; date[5:]
WHY: Position 5 is the first "1" of the month (positions 0 to 3 hold the year, 4 is the dash), and leaving the end out means "to the end".

=== 2.2/3
Q: With `nums = [10, 20, 30, 40, 50]`, what is `nums[3:1:-1]`?
+ `[40, 30]`
- `[]`
- `[40, 30, 20]`
- `[20, 30]`
RUN: nums = [10, 20, 30, 40, 50]; nums[3:1:-1]
WHY: A negative step walks backwards from the start (index 3) and stops before the end (index 1), so it takes indexes 3 and 2.

=== 2.5/2
Q: `queue = ["Ada", "Ben", "Cy"]`. What does `queue.pop()` return?
+ `'Cy'`
- `'Ada'`
- `'Ben'`
- `None`
RUN: queue = ["Ada", "Ben", "Cy"]; queue.pop()
WHY: Without an argument, `pop` removes and returns the last item. Use `pop(0)` to serve the front of a queue.

- `['a', 'C', 'b']`
- `['C', 'b', 'a']`

=== 2.6/2

+ `10.0`

- `100`

RUN: point = (6, 8); (point[0] ** 2 + point[1] ** 2) ** 0.5

=== 3.1/3
Q: With `name = "ada"`, what is `name` after `name.upper()` on its own line?
+ `'ada'`
- `'ADA'`
- `None`

RUN: name = "ada"; name.upper(); name

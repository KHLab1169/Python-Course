=== 4.1/2
Q: With `phones = {"Ada": "555-0101"}`, what does `"555-0101" in phones` give?
+ `False`
- `True`
- `'Ada'`
- `KeyError`
RUN: phones = {"Ada": "555-0101"}; "555-0101" in phones
WHY: `in` on a dictionary checks keys only. To search the values, use `"555-0101" in phones.values()`.

=== 4.1/3
Q: After counting "a b a c a b" with `counts[w] = counts.get(w, 0) + 1`, what is `counts`?
+ `{'a': 3, 'b': 2, 'c': 1}`
- `{'a': 1, 'b': 1, 'c': 1}`
- `{'a': 2, 'b': 2, 'c': 1}`
- `{'c': 1, 'b': 2, 'a': 3}`
RUN: counts = {}; [counts.__setitem__(w, counts.get(w, 0) + 1) for w in "a b a c a b".split()]; counts
WHY: `get(w, 0)` gives the count so far (0 the first time), and one is added. Dictionaries keep keys in insertion order, so "a" comes first.

=== 5.7/3
Q: Why use `ast.literal_eval` rather than `eval` to read `"[1, 2, {'a': 3}]"` from a file?
+ `literal_eval` only accepts plain data and refuses anything that would run code.
- `literal_eval` is the only one that can read lists.
- `eval` can't read dictionaries.
- `literal_eval` is faster.
WHY: `eval` runs any Python expression, so text from a file could delete files or worse. `literal_eval` parses numbers, strings, lists, dicts and similar, nothing else.
